# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

RcinelTranslate: translations keyed by UUIDv7, with clients for .NET, Java and JavaScript, the
`rcinel` command and a web editor with AI drafts. The owner (CodeIsNotEvil) means to publish it, so
treat every public API, file format and doc as something strangers will depend on. Several of the
rules below come from the owner's monorepo, CodeIsNotEvil/MyMonoRepo.

- `dotnet/`: `RcinelTranslate.slnx`.
  - `src/Translate`: the C# client, `Rcinel.Translate` on NuGet. netstandard2.0, no dependencies.
  - `src/Core`: the project model, canonical writing, scanner, checks and export. netstandard2.0.
  - `src/Ai`: AI drafts through the Anthropic SDK.
  - `src/Cli`: the `rcinel` dotnet tool.
  - `src/Editor`: the Blazor Server web editor.
  - `tests/`: xUnit, one project per source project.
- `java/`: the Java client (Gradle, Java 8 bytecode, no dependencies).
- `javascript/`: the JavaScript client (ESM, no dependencies, hand-written `.d.ts`).
- `spec/fixtures/`: the conformance cases all three clients run.
- `docs/format.md`: the file format, which is the contract between all parts. Change it together
  with the code.
- `samples/demo/`: a demo app with a project, used for trying the editor and as documentation.

## Git workflow for Claude

The owner reviews every change. Claude never commits to `main` directly:

1. Start each request on a new branch cut from an up-to-date `main`, with a short kebab-case name
   (`scanner-kotlin-raw-strings`) and no `claude/` prefix, unless the session prescribes a branch.
2. Make small, focused commits.
3. Push the branch and open a pull request against `main` that says what changed and why.
4. Don't merge it. Push review follow-ups to the same branch.

**Everything in this repository appears as the owner's work.** Commit with the owner's identity
(`git config user.name CodeIsNotEvil`, `user.email codeisnotevil@gmail.com`) and without
`Co-Authored-By` lines, session links or other AI trailers. Leave "Generated with" footers out of
commit messages, PR descriptions and docs. Claude must not show up as a contributor.

Don't create or push release tags unless the owner asks.

## Rules that keep the parts in step

- **The three clients behave the same.** Each has its own reader (`FlatJsonReader` in C# and Java,
  `reader.js`), because none may have dependencies. A change to how files are read goes into all
  three and into `spec/fixtures/cases.json`, and all three test suites must pass.
- **Files are written in canonical form only through `CanonicalJson` and `ProjectFiles`** (Core).
  Sorted by id, one entry per line, LF, no BOM. Anything that writes project files another way makes
  the diffs noisy that the whole format exists to keep quiet.
- **Ids are lowercase UUIDv7 and never change.** Sorting by string is sorting by creation time; the
  diff-friendliness depends on it.
- **The code is the source of the source texts.** `translations/<source>.json` is generated by
  `rcinel scan`; the editor never edits it.
- **AI never confirms.** Drafts are stored as `draft` by `ai:<model>`, and a run never overwrites a
  translation a person changed meanwhile (`TranslationDrafter`). The default model is in
  `AiSettings.DefaultModel`.
- **The format has a version** (`format` in rcinel.json). Raise it only for changes old tools can't
  read, and keep reading the old one.

## Style

Formatting comes from `.editorconfig`: two spaces (four in Java and Gradle scripts), LF, UTF-8
without BOM. C# uses file-scoped namespaces and primary constructors; Java is plain Java 8 (no
`var`, no `List.of`); JavaScript is modern ESM.

Namespaces are the project names, `Rcinel.Translate.*` (the owner's choice for this repository; it
departs from MyMonoRepo's `CINE` root namespace, and decision 0008 is still to be revised by the
owner). Because the root namespace is called `Rcinel`, apps can't write `Rcinel.Translate(...)`: C#
binds `Rcinel` to the namespace. Apps call a bare `Translate(...)`, the same shape as Java's
static import and JavaScript's named export `translate(...)` (each client keeps its language's
casing); `rcinel scan` collects all of them: on .NET 6+ the package's `build/Rcinel.Translate.targets` adds
`global using static Rcinel.Translate.Rcinel;` (off with `RcinelTranslateGlobalUsing=false`), older
targets write the `using static` per file. `PackageTests` packs the package and builds projects
against it to keep that working. Inside this repository's own
namespaces `Rcinel` means the class, but a qualified name that starts with `Rcinel.` then fails too:
write `global::Rcinel.Translate....` there (Razor's `_Imports.razor` does).

Build file-system paths with the platform's path API, never by joining strings with `/` or `\`:
`Path.Combine` in C#, `Path.resolve` in Java, `path.join` in Node, `pathlib` in Python. Forward
slashes stay only where a format defines them (URLs, class path resource names).

Comments explain *why* a decision was made, and there are many of them. Keep that density.

Public APIs get XML docs, Javadoc or `.d.ts` comments. The clients build with warnings as errors.

## Containers: Podman and Docker

The owner runs rootless **Podman** without a Docker daemon. `compose.yaml` and the Dockerfile must
work unchanged under `podman compose` and `docker compose`: only Compose-spec features, fully
qualified image names (`mcr.microsoft.com/...`), high host ports, named volumes or plain bind mounts.
Document commands as `podman compose ...`, never `docker-compose`.

## Versions, releases, dependencies

One version for everything: `<Version>` in `dotnet/Directory.Build.props`, `version` in
`java/gradle.properties` and in `javascript/package.json`. CI checks they agree. A release is a
`vX.Y.Z` tag matching them, with a dated section in `CHANGELOG.md`; pushing it runs
`.github/workflows/release.yml`, which publishes to NuGet, Maven Central and npm (README,
"Releasing"). Pushing a tag publishes for real, so only the owner decides when.

The clients have no dependencies and must keep it that way. When the editor, CLI or tests gain one,
check its license fits MIT and mention it in the README's License section.
