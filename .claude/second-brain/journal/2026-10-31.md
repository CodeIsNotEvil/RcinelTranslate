# 2026-10-31

- Built RcinelTranslate from scratch: the format ([[0001-uuidv7-keys-sorted-by-time]],
  [[0002-flat-key-value-json]], [[0005-review-state-by-source-hash]]), the clients
  ([[0004-dependency-free-clients-with-shared-fixtures]]), Core, the `rcinel` tool
  ([[0003-code-is-the-source-of-source-texts]]), AI drafts ([[0007-ai-drafts-never-confirm]]) and the
  editor ([[0006-editor-works-on-the-files]]).
- Guidelines taken over from MyMonoRepo: the editorconfig (UTF-8 without BOM, file-scoped
  namespaces), the PR workflow, the path API rule, the Podman rules, the CINE namespace
  ([[0008-cine-translate-namespace]]), CHANGELOG-driven releases and this second brain.
- The owner asked that commits and GitHub activity appear as CodeIsNotEvil only, without Claude
  as a contributor; written into CLAUDE.md.
- Screenshot preview: the original font size is measured from the image when a box is drawn, so
  "too long" means longer than the real font allows. Gotchas in [[gotchas]].
- Open questions for the owner are in [[rcineltranslate]].
- Release workflow: NuGet with an API key, Maven Central through the Central Portal with
  `com.vanniktech.maven.publish` 0.36.0 (signing tested locally with a throwaway key; the upload
  itself can only be tested by a real release), npm with provenance, then a GitHub release from the
  CHANGELOG section. CI runs first as a reusable workflow.
- The owner wants the namespaces to be `Rcinel.Translate.*` instead of `CINE.Translate.*` and will
  revise [[0008-cine-translate-namespace]] themself. A namespace whose first part is `Rcinel` makes
  `Rcinel.Translate(...)` fail to compile in apps (CS0118, checked with a test project). Asked; the
  owner chose the namespace with a new C# call: `using static Rcinel.Translate.Rcinel;` and a bare
  `Translate(...)`, which `rcinel scan` now collects (only with `""` or a UUID as first argument, so
  other libraries' Translate methods are ignored).
- Found while checking the README snippet: `TryLoad(CultureInfo.CurrentUICulture.Name)` threw in a
  container, where the UI culture is invariant and its name is "". The Try variants of all three
  clients now return "nothing loaded" for an empty language (shared case `emptyLanguages`).
- The owner asked whether a plain `using` could replace `using static`: no, a namespace import
  brings types, not methods. Instead the NuGet package's `build/Rcinel.Translate.targets` adds a
  global `using static` on .NET 6+ (opt out with `RcinelTranslateGlobalUsing=false`). Not
  buildTransitive: a library using the package shouldn't change the usings of the apps using the
  library. `PackageTests` packs and builds real projects; both mutations (no TFM condition, targets
  not packed) were caught.
- One call shape in all three clients, at the owner's request: `Translate(...)` in C#,
  `translate(...)` in Java (static import) and JavaScript (named exports, no `this` in the functions
  so destructuring works too). Each keeps its language's casing; the owner agreed. `rcinel scan`
  collects the bare `translate` with the same """ or UUID first" rule as `Translate`.
