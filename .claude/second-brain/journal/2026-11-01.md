# 2026-11-01

- PR #1 merged. The session couldn't delete its branch (the git connection closes on a delete), so
  the owner deletes it on GitHub.
- "Rcinel" becomes the prefix of all of the owner's future apps, so nothing in this repository may
  claim the bare name. Asked; the owner chose:
  - the command `rtr` (Rcinel TRanslate) instead of `rcinel`; the package stays `Rcinel.Translate.Cli`;
  - the project file `rcinel-translate.json` instead of `rcinel.json`. The old name is still found,
    read and written in place (`TranslationProject.LegacyFileName`).
- Also renamed for the same reason: the editor's sign-in cookie (`rcinel-translate`), since two
  Rcinel apps on one host would overwrite a shared cookie name.
- Decisions 0001, 0003, 0004 and 0007 mention `rcinel scan` and friends; they're append-only, so the
  command names in them are historical. CLAUDE.md, the README and the docs use `rtr`.
- Python and Rust clients, at the owner's request (after weighing the costs of more languages: the
  scanner, the placeholder check and the upkeep per client). Python reads with `json.loads` plus the
  duplicate and non-string checks, since its standard library has a parser; Rust has a hand-written
  reader and keeps the current set in an `RwLock<Arc<_>>`, returning owned strings so a switch never
  leaves anything dangling. Both pass the shared cases. Decision 0004 still says three clients; it's
  append-only, this entry extends it to five.
- `rtr scan` reads `.py`, `.pyi` and `.rs`; the placeholder check knows `{}`, `{:?}` and
  `%(name)s`. f-strings and raw strings can't be read and are reported, not guessed.
- C, C++ and Lua stay open; their pitfalls (pointer lifetime in C, Lua hosts without file access)
  are noted in [[rcineltranslate]].
