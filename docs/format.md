# File format

Version 1. This page is the contract between the clients (C#, Java, JavaScript), the `rcinel`
tool and the editor. Anything that reads or writes these files should follow it, and the shared
cases in [`spec/fixtures`](../spec/fixtures) check that the clients do.

## Ids

Every string has a [UUIDv7](https://www.rfc-editor.org/rfc/rfc9562#name-uuid-version-7) as its id,
written in lowercase canonical form: `01a192e3-5bcc-7000-a8d2-327b1cb0f737`.

The first 48 bits of a UUIDv7 are the Unix time in milliseconds, big-endian. In the lowercase text
form that means **sorting ids as plain strings sorts them by creation time**. Every file below is
sorted that way, so:

- a new string is added at the end of each file, not somewhere in the middle;
- a release's new strings form one block in the diff;
- two branches that both add strings conflict only at the end of the file, where the resolution is
  "keep both".

Ids are compared exactly (ordinal, case-sensitive) by the clients, which is why uppercase ids are
rejected by `rcinel check`: `019A...` and `019a...` would be different keys.

An id never changes and is never reused. If the meaning of a text changes, give it a new id; if
only the wording changes, keep the id and the translations become "outdated" (see below).

## Project layout

A project is a folder, usually `i18n/` next to the app's code:

```
i18n/
  rcinel.json                 the project file
  translations/               shipped with the app
    en.json                   source texts, generated by `rcinel scan`
    de.json                   one file per target language
    pt-BR.json
  review/                     who confirmed what (editor and CLI only)
    de.json
    pt-BR.json
  context/                    help for translators (editor and CLI only)
    notes.json
    screenshots.json
    screenshots/<id>.png
```

Only `translations/` is shipped. The rest is versioned with it but stays out of the app.

## Translation files

`translations/<language>.json` is a flat JSON object of strings, id to text. This is the "key-value
JSON" format that i18next, Crowdin, Lokalise, Weblate, Phrase and most other tools import and export
directly, so a project can move to or from them without conversion.

```json
{
  "01a192e3-5bcc-7000-a8d2-327b1cb0f737": "Einstellungen",
  "01a192e3-5bd4-7005-b3d0-b98f0a9cfe3d": "Speichern",
  "01a192e3-5bd4-7007-bb84-212f497c373e": "{0} Einstellungen gespeichert"
}
```

Readers accept any valid JSON of that shape, plus a UTF-8 byte order mark at the start. They reject:

- values that aren't strings (numbers, `null`, nested objects, arrays);
- a key that appears twice. JSON allows it, but parsers disagree about which value wins, and the
  three clients must show the same text;
- anything else that isn't JSON (trailing commas, comments, single quotes).

Writers (`rcinel` and the editor) always produce the **canonical form**, so diffs only ever show
real changes:

- keys sorted ordinally, which is creation order;
- two spaces of indentation, one entry per line, `\n` line endings, a newline at the end;
- UTF-8 without BOM, non-ASCII characters written as they are (`"Grüße"`, not `"Grüße"`);
- only the escapes JSON requires (`\"`, `\\`, control characters) plus U+2028 and U+2029;
- an empty file is `{}` and a newline.

`rcinel check` warns about files that aren't in canonical form, and `rcinel format` rewrites them.

A file only needs the ids that are translated. An id without an entry shows the source text.

### Language codes and fallback

File names are [BCP 47](https://www.rfc-editor.org/info/bcp47) tags: `de`, `de-AT`, `pt-BR`,
`zh-Hant`. Loading a language reads its **fallback chain** from general to specific and merges it,
so a regional file only needs the strings that differ:

| Loading | Reads |
|---|---|
| `de` | `de.json` |
| `de-AT` | `de.json`, then `de-AT.json` on top |
| `zh-Hant-TW` | `zh.json`, `zh-Hant.json`, `zh-Hant-TW.json` |

Underscores count as dashes (`de_AT`, as Java's `Locale.toString()` writes it). Files of the chain
that don't exist are skipped; loading fails only when none exists.

### Placeholders

Texts may contain placeholders that the app fills in: `{0}`, `{name}`, `{{count}}`, printf-style
`%s` / `%1$d` / `%@`, and markup such as `<b>...</b>`. The files store them as they are. A
translation must contain the same placeholders as the source, in any order; `rcinel check`
reports translations that lost or invented one, and the editor won't confirm them.

The clients leave placeholders alone, except for the convenience overloads: C#'s
`Translate(id, english, args)` runs `string.Format`, Java's fills `{0}`, `{1}`, ... and
JavaScript's fills `{0}` from an array or `{name}` from an object.

## The project file

`rcinel.json`:

```json
{
  "format": 1,
  "name": "Demo Notes",
  "sourceLanguage": "en",
  "translations": "translations",
  "sources": ["../src", "../web"],
  "functions": ["Translate", "translate", "Rcinel.translate"],
  "languages": [
    { "code": "de", "name": "Deutsch", "instructions": "Address the user informally (du)." }
  ],
  "ai": {
    "model": "claude-opus-5-5",
    "effort": "medium",
    "batchSize": 40,
    "instructions": "Keep the product name in English."
  }
}
```

| Field | Meaning |
|---|---|
| `format` | The layout version. Tools refuse newer versions than they know. |
| `name` | Shown in the editor and given to the AI. |
| `sourceLanguage` | The language of the texts in the code. Its file is generated, never edited. |
| `translations` | The shipped folder, relative to `rcinel.json`. |
| `sources` | Folders `rcinel scan` searches, relative to `rcinel.json`. |
| `functions` | The calls `rcinel scan` collects. Add your own wrapper's name here. |
| `languages` | Target languages, in the order the editor lists them. `instructions` are style rules for that language, for the AI and for reviewers. |
| `ai` | Model, effort (`low` to `max`), strings per request, and instructions for every language. |

## Review files

`review/<language>.json` records who stands behind each translation, one line per id:

```json
{
  "01a192e3-5bcc-7000-a8d2-327b1cb0f737": { "state": "confirmed", "source": "74a883a037bc227f", "by": "alex", "at": "2026-10-31T16:40:00Z" },
  "01a192e3-5bd4-7000-8e32-166cb3e992e1": { "state": "draft", "source": "9b7878aef90b527c", "by": "ai:claude-opus-5-5", "at": "2026-10-31T16:35:00Z" }
}
```

- `state`: `draft` (written by the AI or saved unfinished) or `confirmed` (a reviewer approved it).
- `source`: the first 16 hex digits of the SHA-256 of the UTF-8 source text the translation was
  made for.
- `by`: the editor user, or `ai:<model>` for AI drafts.
- `at`: UTC, to the second.

From these, every translation has one of four states:

| State | Means |
|---|---|
| Missing | No entry in the translation file. The app shows the source text. |
| Draft | Translated, but not confirmed, or nobody reviewed it (an entry without a review line, for example typed into the file by hand). |
| Outdated | Was reviewed, but `source` no longer matches the current source text: the English changed. |
| Confirmed | Confirmed for the current source text. |

Progress is counted over the ids in the source file. Translations of ids that are no longer in
the source stay ("orphaned") until `rcinel prune`, so a string that comes back after a revert keeps
its translations.

## Context files

`context/notes.json` is a flat object like a translation file: id to a note for translators
("verb, on the save button").

`context/screenshots.json` lists screenshots by id (a UUIDv7 as well), each with the strings marked
on it:

```json
{
  "01a192e4-0000-7000-8000-5c4ee05e0001": {
    "file": "01a192e4-0000-7000-8000-5c4ee05e0001.png",
    "title": "Settings",
    "width": 1280,
    "height": 800,
    "regions": [
      { "key": "01a192e3-5bcc-7000-a8d2-327b1cb0f737", "x": 0.2453, "y": 0.0488, "width": 0.1525, "height": 0.0462, "align": "left", "background": "#eef1f6", "color": "#1d2433", "fontSize": 0.0375 }
    ]
  }
}
```

Region coordinates and `fontSize` are fractions of the image (0 to 1; `fontSize` of its height), so
they survive a screenshot being replaced by one at another resolution. `background` and `color`
paint the preview; `fontSize` is the size of the original text, measured from the pixels when the
region was drawn, and is left out when unknown. Regions are sorted by key, then position.
